# 功能、需求與介面核對報告

日期：2026-10-02。基準：需求 v0.4、程式 0.1.0（起始 commit `65f6609`）；本輪加入系統暗色模式及現有功能修正。這是一份現況審查，不是全產品驗收證書。

**結論：目前尚未完整實作需求。** FR01～06、FR13～14 只有部分流程，FR07～11 尚無完整業務模組，FR12 只有同步錯誤提示；Google Drive 設定完成不代表帳務模組已完成。既有基礎功能通過下列模擬測試；真實多裝置、故障與全部原始驗收仍未完成。完整交付依需求仍需 M0～M4，沒有刪除或降級原需求。

## 1 核對方式與證據範圍

- 逐章閱讀需求正文、附錄完整分類與 AT01～AT90；對照 `src/domain`、`application`、`infrastructure`、`stores`、五個頁面及所有表單。
- 檢查 schema 是否可表達需求、應用流程是否執行、UI 是否能操作，再查測試。只有型別、種子名稱或空的 Drive 目錄，不計功能完成。
- 執行金額／投影／儲存／REST 契約測試及 Chrome Playwright。瀏覽器使用獨立設定與模擬 GIS／Drive；本輪未向使用者真實帳本新增測試帳務。
- 亮／暗、1440×1000／360×800 擷取各既有頁面、帳戶編輯、交易明細、錯誤與 pending；檢查水平溢位與可見文字對比，並檢查主題切換時的輸入及連線狀態。
- 每個 AT 的原情境、預期、現況與限制保存在 [90 項驗收矩陣](acceptance-matrix.csv)。「已測・單元」或「已測・模擬」只代表所述層級，不是實機雲端驗收。部分通過不把整個 AT 標為通過。

## 4 已修正問題與規格差異

| ID／嚴重度 | 問題及影響 | 本輪處置／仍需注意 |

| F03／P2 | 跨幣轉帳明細只顯示來源本金，無轉入合計與實扣 | 補目的帳戶／幣種／合計、來源本金＋淨費用、商家；新增跨幣 E2E |
| F04／P2 | 快取提示未直接顯示確認時間 | banner 補上最後已確認時間，繼續標為等待雲端核對 |
| F05／P1 | 缺暗色、許多淡灰文字對比不足、部分按鈕過小 | 新語意色彩 tokens、系統 dark media、PrimeVue 同步；44px 主要／圖示控制、手機表單單欄；對比及溢位測試 |
| F06／P2 | 帳戶表單「信用欠款」文案容易被誤認為信用帳務已完成 | 明示負數只記既有欠款，信用額度／帳單尚未提供 |
| D01 | 期初直接放 account.openingBalance，不是專用期初 Journal；建立後全面鎖定幣種／期初／信用性質 | **尚未與完整 §3.1、§5、§17 對齊**。保留現有資料；需設計 schema 遷移與修訂歷史後補齊 |
| D02 | 只有三類 Transaction，fee 嵌入轉帳，缺 Journal／Posting／Allocation | **暫行架構與完整領域模型不同**。目前三類雙邊計算有效，不能直接拿來承載系統正負混合、退款與清償 |
| D03 | 一操作一檔、全量讀取；無 batchId、deviceId、change cursor／快照 | **只完成同步方案的一部分**。本機鎖不等於跨裝置鎖，正式共同上限須先驗證再開自動帳務 |
| D04 | 固定 Asia/Taipei、幣種精度固定、沒有交易／入帳日雙軌 | **與完整可設定時區／報表日期設計不同**，須後續補齊；本輪報表明示交易日 |
| D05 | account fork 會暫停所有引用該帳戶的交易，含無爭議祖先交易 | **比 §16.3 最後無爭議狀態更保守**，可能暫時降低顯示餘額；目前有衝突提示與既有測試，尚缺完整候選金流／解衝突 UI。不能宣稱跨裝置已完整驗收 |
| D06 | 重整需要重新授權 | **符合現行 memory-only 決策**。sessionStorage 方案尚未獲使用者選定，這次沒有改憑證保存方式 |
| D07 | 外觀跟隨系統 | **本次新增需求**，即時依 prefers-color-scheme 切換。無額外帳戶偏好／token／儲存內容；目前不另提供手動覆寫選項 |

D01～D05 是已公開的實作差距，不是要求接受刪除功能。補齊需按原 M1～M4 及相依模型順序進行。新的 schema 不得直接讓既有 Drive 帳本無法讀取，需先做遷移及備份方案。

## 6 完整性與下一步

- **P1：先補 M0／M2 的安全基礎**：真實多裝置、正式操作衝突解決、changes 掃描補讀、完整備份／還原與 schema 遷移。現況不能承諾零漏帳或銀行等級並發隔離。
- **P1：補齊 M1**：Journal／Posting／Allocation、六種紀錄、應收應付結清、分類／幣種管理、正式修訂與退款；用原 AT 逐項驅動，不先堆沒有運算的設定表單。
- **P1：M3／M4**：信用與帳單群組 → 週期分期／日期引擎 → 回饋／儲值 → 自動處理與完整報表；所有自動金流仍只是記帳。
- **P2：介面補測**：`impeccable adapt` 對應行動實機／200% 文字；`impeccable harden` 對應衝突與還原；`impeccable optimize` 對應資料量／bundle；新模組完成後再以 `impeccable polish` 做最後整合，不為外觀評分刪減需求。

本輪詳細驗證結果見 [進度紀錄](progress.md)。未實作項目不會因既有測試全綠而變成已完成。
