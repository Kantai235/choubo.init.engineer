## 1 雲端與本機各自保存什麼

| 位置 | 保存內容 | 清除與復原原則 |
| --- | --- | --- |
| 使用者 Google Drive | 正式交易、全部明細與分錄、帳戶、幣種、分類、規則、分配、排程狀態、衝突解決、縮圖、快照及備份 | 正式資料來源；所有裝置從這裡重新取得 |
| 記憶體 | access token、當次需要的帳務資料、表單及計算結果 | 關閉後可消失；重新取得授權並從 Drive 載入 |
| localStorage 連線資訊 | 使用者識別、folderId、bookId、格式版本、顯示偏好、同步資訊 | 都是連線提示或可驗證索引，不能單靠它們證明已授權 |
| localStorage 可丟棄快取 | 小型摘要、最近檢視資料與其對應版本 | 設定固定容量，超出先清舊快取；可由 Drive 重建 |
| localStorage 受保護暫存 | 草稿、operationId、尚未確認上傳結果的完整操作內容 | 不當成可丟棄快取；確認 Drive 已保存或使用者明確捨棄後才刪除 |

access token 建議只放記憶體，refresh token 與 client secret 不放前端。localStorage 可被同來源的 JavaScript 讀取，因此不適合作為長期保存授權憑證的位置；記憶體保存亦不免除輸入驗證與第三方程式控管。[OWASP HTML5 Security](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html)

Google 的瀏覽器 token 模式允許前端直接呼叫 API；token 過期後須由使用者操作重新取得。介面提供「重新連接 Google Drive」，保留草稿並在完成後繼續，不宣稱可以永久免互動續期。[Google token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model)

暫定可丟棄快取以序列化後約 1 MiB 為預算，實際依目標瀏覽器量測；草稿與未確認操作另行保護。這是可調整的工程預算，不是每個瀏覽器都保證的可用額度。本機空間不足時先清快取，仍失敗則明示草稿尚未安全暫存，保留表單並提供下載，不能假裝已保存。首次版本不需要為完整離線帳本引入大型本機資料庫。

歷史交易按查詢月份或期間從 Drive 載入，不把所有雲端日誌永久複製到 localStorage。報表與回饋必須取得完整需要的範圍或經版本驗證的摘要；不能因只載入最近月份，就將不完整資料顯示成全年總額。

## 2 使用流程與自動同步

首次使用提供「連接 Google Drive」作為入口。授權後查找本人擁有的網站專用資料夾，有資料就載入，沒有才在根目錄建立。既有 v0.2 本機資料可在歸屬確認後一次導入，不能因產品改為雲端就丟棄尚未上傳的舊資料。

每次開啟及恢復前景先檢查授權、讀取可用的雲端變更，再執行到期事項。提交交易會自動上傳；前景期間以可調整的低頻增量檢查取得其他裝置變更。背景暫停輪詢，恢復前景補讀；關站不要求最後一瞬間的網路請求一定成功。

### 推薦的保存流程

1. 使用者輸入時保存有所有者綁定的草稿；草稿不列入正式餘額。
2. 按儲存後先同步可取得的雲端資料，檢查帳戶、規則、金額、來源與版本。
3. 形成完整操作組，包括主紀錄、所有明細及當次必要的費用、儲值、分配等；保存固定 operationId 與待提交內容。
4. 上傳不可變操作批次，驗證 Drive 的檔案結果。回應不明時先用相同 ID 查回，不能直接換一個 ID 再新增。
5. 確认雲端保存後建立有效帳務結果，再拉取增量、檢查並發衝突及更新同步狀態。
6. 保存結果已確認且資料可從 Drive 重建後，清除對應待提交暫存，保留必要的草稿處理歷程。

正式餘額只含已確認保存且未被衝突暫停的有效操作；提交中的變化放在預覽或待處理區。已上傳資料之後若發現並發衝突，應標示受影響結果，不能刪掉其中一方來假裝從未存在。

| 情況 | 推薦行為 |
| --- | --- |
| 網路及授權正常 | 自動讀取、提交與同步；使用者不必另按同步按鈕 |
| 暫時斷線 | 已驗證工作階段可查看已載入資料、編輯草稿；停止正式提交與自動帳務 |
| token 過期 | 保留草稿與待確認操作，提示重新連接；不自動跳出反覆授權視窗 |
| 恢復連線 | 先讀雲端、重驗證；未按過提交的草稿保持草稿；先前已按提交的操作可在無變更衝突時續送 |
| 上傳成功但回應丟失 | 查回相同操作；若已有有效結果，不重複入帳 |
| 雲端規則或原交易已變動 | 顯示更新後的影響，必要時重新確認；不以舊草稿覆蓋新資料 |
| Drive 配額、權限或服務失敗 | 保留待處理；可重試錯誤採退避，權限問題要求重新連接或處理 |

對使用者顯示「正在儲存」「已同步，時間」「等待連線」「需要重新連接」「需要處理衝突」。已同步只表示同步到最近一次成功取得的雲端狀態，不保證其他裝置此刻沒有新的提交。Drive 的速率與暫時性伺服器錯誤按官方建議退避重試。[Google Drive 錯誤處理](https://developers.google.com/workspace/drive/api/guides/handle-errors)

### 雲端為準的具體定義

本機快取與雲端已驗證資料不一致時，重建快取。本機未提交的修改保留為草稿，讓使用者套用到新版本。兩台裝置各自已上傳的相反修改，則是雲端內的衝突，不能用「雲端為準」或最後修改時間自動選掉其中一筆。

不同且沒有共同限制的交易可合併；同筆修改、同一原單超額退款、同帳單超額分配、同一回饋上限及自動繳款來源不足，須驗證共同條件。例：原單可退 100，兩台各新增退款 80，不能直接將 160 當作合法本金退款。實際確有超額收款時，另分為可分配退款及其他用途，保留真實資金流。

同一自動期次由 bookId、計畫 ID 及名義期次形成穩定生成識別；改日期或規則版本不因此變成第二個期次。同 ID 同內容去重，不同內容形成衝突。受衝突影響的自動操作暫停，其餘不相關功能仍可使用。

## 3 雲端資料格式與版本

保留不可變操作批次及可重建快照的方向，避免所有裝置覆蓋同一份完整帳本檔。一次本機提交是一個完整帳務操作；上傳時可將數個已準備好的操作合成一個批次，仍保存各自的 operationId。多筆明細不各自建立 Drive 檔案。

專用資料夾內保存帳本識別、operations、snapshots、backups 及 assets。圖片先上傳並確認可讀，再提交資源引用；尚未完成的圖片不能被描述為已備份。操作內容與歷史資源不因建立較新快照就立即刪除。

快照包含覆蓋哪些操作及各實體版本，供快速建立餘額、未結清與索引；月份查詢快照按需取得。補登舊月份交易時，要讓相關舊月份摘要失效或更新，不能只更新目前月份。尚未驗證完整的摘要明示載入中或不完整。

首次同步採「取得起點游標 → 分頁掃描 → 從起點補讀變更 → 完成後保存新游標」，避免掃描期間的變更遺漏。增量游標須和已載入的資料版本一起使用；清空快取後不能只沿用舊游標而忽略過去資料，應由雲端快照與所需批次重建。[Google Drive 變更追蹤](https://developers.google.com/workspace/drive/api/guides/manage-changes)

每次回應核對帳號、bookId 及當次連線識別，防止切換帳號後舊請求寫入新帳號畫面。使用者識別由 Google 的已授權資訊確認，不能只信 localStorage 的電子郵件。清除快取不清除 Drive 正式帳本；登出、清草稿、斷開授權、刪除雲端資料為不同操作。

資料保存 schemaVersion 與最低可寫入程式版本。舊分頁遇到不支援的格式進入唯讀並提示更新；格式遷移先建新快照、驗證再切換，保留舊版復原點。這些是應用層協定，仍需驗證並發與故障，不視 Drive API 為資料庫交易鎖。

## 4 帳單額度與付款的推薦規則

### 帳戶角色與群組

預設記帳帳戶、額度群組代表、帳單群組代表及付款來源分開保存。共用額度不自動合併帳單；合併帳單成員初版限相同幣種及共同帳期。每個帳戶同時至多屬於一個有效額度群組及一個有效帳單群組。

群組設定於下一個完整帳期生效。過去獨立帳單保留原來的到期日及付款政策，不能因加入群組就漏掉歷史未付；新群組帳期只由群組建立一套自動繳款。退出或變更代表也不搬移歷史消費。

建議群組可用額度＝核定額度－各成員已入帳欠款正值合計－未入帳保留額合計。每個成員的溢繳預設不增加核定額度，也不自動替另一成員抵欠款。實際消費可顯示超額；額度不足時不虛構成功的自動儲值。

### 欠款與折抵

每筆欠款有唯一來源，帳單只引用它。上期未付在下期顯示結轉時，不建立第二份欠款；清償一次後，所有引用處同步反映剩餘額。付款、退款及回饋入帳對帳戶生效一次，分配到帳單不再增加第二次餘額。

沿用已確認折抵規則：合格正向款項分配至最近已結帳未付清帳單，含到期日，保留人工分配。超過可分配額或期限後的正向款項，先保留為未分配信用餘額；可在後續符合條件的帳期分配，不能默默把已逾期帳單標成已付。

正向款項預設只分配本帳戶的欠款。即使正附卡合併帳單，也不默認 A 卡溢繳可清 B 卡欠款；若實際銀行如此處理，以明示的跨成員分配調整記錄，保存來源與去向。

### 自動繳款

到期日取得雲端資料後，依當時已知的折抵及付款計算全額剩餘應付。同一天多張帳單，先處理到期日較早者，同日以固定帳單識別排序；逐張重新檢查來源餘額。每張全額成功或待處理，不自動改部分繳款。

自動來源初版採同幣種、非信用的資產帳戶。合併帳單先檢查全群組所需總額，再用一個操作組建立各成員的配對轉帳；不能只成功支付其中一張卻顯示群組全額完成。手動部分繳款仍保留。

若未分配正向款造成帳單應付與淨欠款有明顯差異，先提示分配待處理，避免盲目再記溢繳；不能擅自將較小付款金額當作全額成功。付款完成後才新增的退款另記正向餘額，不回寫已完成的付款。

結帳日沿用 1～30 日／月初／月底及短月回退；結帳後天數推薦至少 1 日。到期日預設不套用週期的工作日調整，可逐期依實際帳單覆寫並保存原因。結帳後補登前期項目以帳單調整處理，保留原快照及原付款，不再建立第二份相同帳單。

## 5 週期分期退款與提前清償

週期每期是一個新事件；分期各期共享原始購買識別但有獨立期次。原始購買總額用於計畫與分析，各期本金用於實際入帳，不能兩者都計入支出。收入分期的利息列收入；借款還款的本金只減少既有債務，利息才列支出。

### 分期本利與日期

| 項目 | 推薦預設 |
| --- | --- |
| 金額輸入 | 本金與總利息分開；無息為 0；不代算銀行貸款利率 |
| 分配 | 本金與利息各自依精度、進位及尾差首／末期設定分攤，各自加總守恆 |
| 首期覆寫 | 分開輸入首期本金及利息；若與尾差首期衝突，要求改相容設定，不靜默改尾差位置 |
| 寬限期 | 首期錨點及後續期次一起順延 0／1／2 個月；保留原名義日，短月回退不造成後續漂移 |
| 寬限利息 | 總利息不變；實際增加或減免時由使用者調整輸入並預覽 |
| 從中途接手 | 依原本利表標記前期已處理，只生成剩餘期；剩餘本金與利息分開驗證 |
| 工作日 | 週末加自訂休假／補班；每期從名義日期調整，不用前次調整後日期推下一期 |
| 貸款還款 | 連到既有 Obligation，不每期新增借入；初始借款與收付款排程分開 |
| 巢狀設定 | 同一模板的週期與分期初版互斥；系統自動衍生項不再建立另一層自動排程 |

### 分期退款必須按實際處理方式分配

不能假定退款一定取消未來分期。推薦提供三種明確操作，預覽對帳戶、帳單、剩餘本金、利息與額度的影響。

| 方式 | 本次現金或信用帳戶效果 | 未來分期效果 |
| --- | --- | --- |
| 已退回款項，分期照常 | 依實際退款增加帳戶餘額或減少信用欠款 | 原排程與保留額維持；避免同時取消本金而重複受益 |
| 取消未入帳本金 | 該部分不再建立一次已收到的退款金流 | 減少未來本金與對應額度保留；依取消分配更新期次 |
| 混合處理 | 只對實際已退回部分入帳 | 其餘明確分配至取消的未來本金；兩部分合計等於本次退本 |

例：原本金 12,000，已入帳 2,000、未入帳 10,000，退款 3,000。若已收到 3,000 而原分期維持，未來本金仍是 10,000。若實際取消未來本金 3,000，未來本金改為 7,000，但這部分不再加一筆收款 3,000。若兩者都做，便會重複抵減。

取消未來本金而未指定期次時，推薦從最後一期往前取消，保留近期已知繳款安排；允許按實際新分期表重新分攤。未入帳利息是否減免由使用者依實際情況輸入，不自動假設按比例退息。已入帳利息與手續費只有實際退回時才沖回。

退款本金同時受到原交易與各明細剩餘可退額限制。外幣以原幣淨本金檢查上限，實收帳戶幣金額獨立保存；例如原扣 3,200 TWD、退回實收 3,500，原成本回沖 3,200，匯差 +300 另列。沒有原單的退款可手動分類並填原因，但不猜測原回饋或原費用。

### 提前清償

提前清償與商家退款分開操作。信用消費分期先把選定未入帳本金轉成待清償欠款，同額釋放保留，再建立付款；貸款已有完整債務時只結清剩餘本金，不再建立一次債務。使用者輸入實際應付利息、減免與手續費，系統提供總額預覽。

完成後原未來期次標記已被提前清償取代，後續重開或同步不得再生成。來源不足則不自動改部分清償，保留為待處理。

## 6 紅利回饋與儲值的推薦規則

### 回饋計算單位

保留百分比、完整比例級距及固定額三種方式，基本與活動回饋可疊加，互斥群組選最高優先序，優先序相同再以穩定規則 ID 排序。活動說明文字供閱讀，計算只能使用明確的條件欄位。

| 項目 | 推薦定義 |
| --- | --- |
| 消費回饋與儲值回饋 | 規則明示適用 purchase 或 topup；普通轉帳預設不適用 |
| 同筆多明細 | 先依規則篩選合格行，扣掉折扣與相關退款，再合計為本筆基數 |
| 消費次數 | 同一規則及計算區間內，按不同原始消費識別計次；明細與分期不放大次數 |
| 週期消費 | 每期是新事件，符合資格就各計一次 |
| 每期分期回饋 | 金額基數採該窗口內各期已符合入帳條件的本金，同一原消費合併計算單筆條件；不含利息與費用 |
| 首期分期回饋 | 首個應領期次以原消費合格本金計算一次；後續不再領相同全額回饋 |
| 固定每筆 | 一筆原始消費對同一規則最多有一次有效固定回饋；初版不把分期各期當新的一筆 |
| 固定每區間 | 帳戶或明訂累計群組，在該規則的一個區間達標後只領一次 |
| 跨幣回饋 | 必須指定回饋單位及換算比例，不能將 TWD 百分比金額直接當成相同數量點數 |

計算依序為：適用篩選與退款折扣 → 同筆合格基數 → 單筆低消 → 合格事件的累積金額及次數 → 區間門檻 → 單筆進位與上限 → 區間進位與上限。多門檻採全部滿足。達門檻後追溯全期合格事件，單筆不合格事件不加入門檻累計。

回饋上限限制該區間的應得額，入帳日期或規則版本變動不會自動重置已使用上限。同一活動分數次入帳，以應得總額減掉已入帳淨額及有效待入帳額處理差額；待入帳預留與正式入帳不能各占一次上限。

門檻尚未成立時顯示預估。已符合資格且到了設定日期才正式入帳；當下交易後的回饋若之後受退款、上限或門檻變化影響，使用差額調整保留歷程。單筆回饋與整期回饋都有穩定來源，重算不是新增另一筆完整回饋。

### 退款及規則變更

退款回到原活動與原計算窗口重驗資格。若原累積 3,000 才可領 60，退款後只剩 2,900，可能整期 60 都須追回；不能一律只追回退款額乘回饋率。提交退款前顯示受影響的其他交易與整期差額。

預設允許回饋帳戶出現負點數並提示待補，避免回饋已使用就把追回額忽略；人工確認不追回時，保存明確調整原因。原單不存在時不推測回饋追回。每期分期回饋按實際受調整期次重算，首期全額回饋按調整後原消費本金重算。

既有交易保存規則版本。修改門檻、單位或上限預設從下一計算區間生效；改本期須提供影響預覽及明示重算，不能靠改名稱或版本 ID 重新領一份固定回饋。

### 自動儲值與低餘額

沿用已確認算法：固定前／後儲值各觸發一次；補差額只在消費後餘額低於 T 時補至 G。判斷使用整筆明細、折扣及同次扣款費用後的淨扣款，不能逐行觸發。

初版自動儲值限同幣種，目的為非信用的資產或儲值帳戶，來源可為另一資產帳戶或信用帳戶。來源為信用時檢查可用額度，成功後增加信用欠款；儲值本金不列支出。信用帳戶間繳款使用信用繳款流程，不再套成一般儲值。

儲值回饋基數預設成功轉入本金，不含手續費；只有設定了適用 topup 的規則才計算。禁止來源循環，自動轉帳及回饋不再啟動第二層儲值。

來源不足時不建立成功轉帳。已實際發生的消費可由使用者明確選擇保留，包括必要的負餘額，並顯示待處理儲值；不能用失敗的儲值結果假裝帳戶已補足。低餘額提示預設於整筆消費及成功儲值處理後判斷，避免正常補足後仍跳一次瞬間低餘額警告；儲值失敗另發通知。

## 7 明細應收應付與報表的推薦規則

每筆仍共用帳戶、幣種、日期時間；轉帳共用帳戶對。商家、發票及整筆備註共用，每行有分類、名稱、金額、選填備註及回饋適用性。相反資金方向的借出與收回不能混成同一主紀錄；結清操作可一次提交數筆各自合法的紀錄。

整筆折扣按合格行金額比例分配最小單位，尾差依餘數及穩定 lineId 排序。退款必須指定原行或選明確的無原單模式；分期表同時滿足每行總本金及每期總本金，利息獨立分配。

| 項目 | 推薦處理 |
| --- | --- |
| 支出及收入 | 依行分類統計；主紀錄總額只作摘要 |
| 轉帳本金及信用繳款 | 僅作資金移動，不重列收支 |
| 借出／借入 | 建立應收／應付本金，不直接列收支 |
| 收回／還款 | 透過結清分配減少既有本金；利息另列系統收入或支出 |
| 替他人代付 | 直接建立應收，不再建立自己的消費支出 |
| 自己支出後申請報帳 | 先保留支出；申請中不重建現金流，核准部分以非現金調整轉為應收並沖減對應支出 |
| 報帳收到款項 | 收款並結清應收，不再次認列收入；真正獨立補助則用收入用途 |
| 呆帳或債務減免 | 明確調整結清並記錄原因，不刪除原本金歷程 |
| 匯兌差額 | 與原本金成本回沖分開，可在報表獨立呈現 |
| 國外交易費用 | 以整筆合格本金計算一次，保留實收覆寫；分期預設首期收取一次，實際逐期收費另保存對應設定 |
| 退款退費 | 累計不超過原費用，最後一次處理尾差；實際退費覆寫要有原因 |

總覽顯示帳戶資產、已入帳信用欠款、應收及應付，另列未入帳分期本金；主要淨額與含未入帳分期的估計淨額分開，避免讓額度保留直接變成第二筆正式負債。應收應付預設納入資產負債；若已有代表同一項債務的帳戶，必須建立映射，只計入一個來源，綁定後不允許兩邊各自任意改餘額。

關閉帳戶的納入總額只影響其總覽歸屬，不刪交易、不排除日常收支、不停用帳單與通知；若它是債務代表帳戶，同一映射項目隨其總額設定處理，不能另從內部負債加回去。缺匯率項目以原幣列為未估值，不當成 0。

分類保留支出預設兩層、其他預設一層，自訂建議最多三層。新增子分類不改歷史 categoryId；往後新增紀錄選可用葉節點。有歷史的帳戶、分類採封存；幣種的入帳精度不能直接改寫舊金額，每筆精確值都須能知道其單位與精度。

## 8 編修自動執行與通知

來源與衍生紀錄各有穩定識別、規則版本及管理狀態。修改已入帳來源時先列出影響，採原分錄沖銷加修正版；退款是後續事件，與刪除錯誤紀錄分開。

使用者將回饋或儲值改為手動時，保留歷史來源並解除自動管理；相同生成識別保留已接管或已抑制狀態，重算不再產生第二份。刪除消費時，已實際發生的儲值預設保留，未實際發生的預估項可撤銷，最終依影響預覽提交完整操作組。

自動事件只在網站開啟、已連接 Drive 且相依資料沒有未解衝突時正式執行。前景計時器、恢復前景及同步完成都能觸發檢查；關站期間不執行，重開後保留名義日、實際處理時間及帳務生效日。

事件依日期及依賴關係處理，不能只是把所有規則跑一遍。先取得已知交易及到期分錄；到帳期截止才能結帳；以帳單區間計算的回饋在帳期確定後結算；符合回饋入帳時點的正向款才能分配帳單；最後計算到期付款。回饋不再回頭變成可領回饋的消費，避免循環。

長期未開啟時先列摘要，固定且無衝突的已授權排程可補執行；金額改變、來源不足、缺匯率或受歷史修訂影響者轉待處理。實際銀行付款時間未知時，不因補記而宣稱已準時扣款。

通知以事件識別去重，低餘額回升後再跌破才重置；已讀與已處理分開。未結清帳單仍持續顯示在待辦，不因使用者已讀提醒而消失。

## 9 備份還原與資料安全

雲端同步之外，另保留可還原快照。推薦有變更且網站有開啟時形成每日復原點，保留最近 7 個日版本及 4 個週版本；無開站的日期不承諾產生備份。版本包含資料、規則、分配、已執行排程及資源清單，資源存在且可驗證才標記完整。

完整匯出使用包含 JSON 與縮圖內容的打包檔，或小型資源內嵌格式。CSV 只供分析。備份不含 access token、refresh token、可直接套用到另一帳號的連線憑證或裝置同步狀態。缺少某張圖片或批次時明示缺項，不把不完整檔案當完整備份。

還原預設建立新的 bookId，先預覽帳戶餘額、未付帳單、分期及回饋；選用後將舊帳本保留為封存資料集。新帳本保留已執行／已撤銷期次的狀態，不能因 bookId 改變就重新領回饋或再繳一次款。複製來源識別與去重狀態須一併遷移及驗證。

各裝置在提交前重新確認作用中的資料集。舊裝置若仍將操作寫入舊 bookId，資料保留在舊資料集並提示重新載入，不直接併進新帳本；需要取回時逐筆檢查後匯入。這樣可以避免恢復較早備份後，又被另一裝置自動加回全部較新操作。

多裝置同時進行還原時，保留兩個新資料集，請使用者選擇，不依最後寫入時間刪除其一。作用中帳本的設定不承載唯一財務內容，即使指標需修復，各資料集仍可依 ID 找回。
